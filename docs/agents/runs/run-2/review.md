# Run 2 review (by the human-directed reviewer, not by the agents)

Reviewed the branch as pushed (commit b9a174d), against the pinned app, Playwright 1.64.1, Chromium. The guidance file was written after run 1 had been reviewed, so it answers run 1's problems; this is a test of "does guidance help", not of "do agents guess the conventions".

1. Lint and type-check: `npm run lint` and `npx tsc --noEmit` pass with no findings.
2. Locators: no CSS workaround of its own. Uses `getByRole('textbox', { name: 'Write a comment...' })`, `getByRole('button', { name: 'Post Comment' })`, and the suite's existing `ArticlePage.comment()` and `heading()`. The icon-only delete button is reached as `card.getByRole('button')`, with a comment saying why. No `.first()` or `.last()`.
3. Assertions can fail: with `comment-not-saved.patch`, 5 of the 6 tests that pass on the unpatched app fail (post, persist, delete, other user's comment, delete-one-of-two); "posting an empty comment does not add a comment" passes, as it should. With `comment-delete-noop.patch`, the two tests that delete a comment fail on "comment is hidden" ("a user can delete their own comment", "deleting one comment leaves other comments intact"); the post, persist, empty and other-user tests pass, as they should. The dismiss test fails everywhere (see below), so it proves nothing. Several tests also check the result through `api.listComments`, not only on the screen.
4. Isolation: each test creates its own article through the API; unique comment text comes from `buildArticle().body` (the suite's builder, used for a comment because there is no comment builder, and said so in a comment). Three stress runs (6 workers, shuffled, each test repeated 5 times): 30 passed and 5 failed, three times. The 5 failures are always the dismiss test.
5. Plan versus app: matched the running app (form text, empty state, confirm text, one icon-only button per own comment, none on another user's comment). Wrong or unverified: the planner said "Guidance rule 13" and "rule 14" (the file has bullets, not numbered rules); it did not try the empty-comment case in the app; it logged one console error and did not look into it; the generator header comment names `specs/plan.md`, which does not exist.
6. Defect hiding: none. No `test.fixme`, no `test.skip`, no loosened assertion, no removed expected-failure marker.
7. Conventions: used `authedTest`, `workerUser`, `otherUser`, `api`, `buildArticle` and `ArticlePage`. Did not add anything to the page object or builders (the generator agent has no file-edit tool beyond writing the spec); the planner suggested page-object additions that nobody applied.

One of seven generated tests fails on the unpatched app: "dismissing the delete confirmation keeps the comment" times out after 35 seconds. It registers `page.waitForEvent('dialog')` and then awaits `deleteButton.click()` before awaiting the dialog; the click does not finish while the dialog is open, so the test deadlocks. It is a test bug, not an app defect. All seven generators reported that they did not run their test (no test runner in their tool set), which is exactly the case the guidance line "run the test before you hand it back" could not be followed in.
